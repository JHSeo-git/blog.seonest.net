# Ralph Loop

<PostMeta createdAt={metadata.openGraph.publishedTime} updatedAt={metadata.openGraph.modifiedTime} />

> "Ralph is a Bash loop" — Geoffrey Huntley

2026년 1월 현재, 개발자 커뮤니티에서 가장 자주 오르내리는 이름은 **Ralph Loop**(또는 Ralph Wiggum 기법)입니다.
심슨 가족의 캐릭터에서 이름을 가져온 이 기법이 하는 일은 하나입니다. 같은 프롬프트를 AI 코딩 에이전트에 계속 물려서, 작업이 끝날 때까지 스스로 돌게 만듭니다.

## 1. Ralph Loop란 무엇인가?

Ralph Loop는 Geoffrey Huntley가 창안한 자율 AI 개발 방법론입니다. 가장 순수한 형태는 셸 한 줄입니다:

```bash title="bash"
while :; do cat PROMPT.md | claude-code ; done
```

이게 전부입니다. 같은 프롬프트를 계속 먹이면서, 작업이 끝날 때까지 에이전트를 다시 실행합니다.

### 핵심 아이디어

전통적인 AI 코딩 세션의 문제점은 다음과 같습니다:

- AI가 다 끝났다고 판단하면 그대로 멈춥니다
- 대화가 길어지면 컨텍스트가 오염됩니다(context pollution)
- 실패한 시도가 대화 기록에 쌓이면서 AI가 방향을 잃습니다

Ralph의 해결책은 간단합니다:

- **진행 상태는 LLM 컨텍스트가 아니라 파일과 Git에 저장합니다**
- **컨텍스트가 가득 차면 빈 컨텍스트의 새 에이전트로 교체합니다**
- **이전 반복의 작업물은 파일 시스템에서 읽어 이어 갑니다**

## 2. 왜 Ralph Loop가 필요한가?

### 전통적인 AI 코딩의 한계

1. **조기 종료**: AI가 충분하다고 판단하면 작업이 끝나기 전에 멈춥니다
2. **프롬프트 한 번의 한계**: 복잡한 작업은 프롬프트 한 번으로 끝나지 않습니다
3. **다시 시키는 비용**: 사람이 매번 손으로 다시 지시해야 합니다
4. **컨텍스트 손실**: 대화를 새로 시작하면 이전 진행 상황이 사라집니다

### Ralph의 장점

- $50,000 계약 작업을 API 비용 $297로 끝낸 실제 사례가 있습니다
- Y Combinator 해커톤에서는 하룻밤에 저장소 6개를 배포했습니다
- Jest → Vitest 전환, 프레임워크 업그레이드 같은 마이그레이션을 자동화합니다

## 3. 핵심 철학과 원칙

### 매번 다르게 틀리는 것보다 매번 똑같이 엉망인 편이 낫습니다

Ralph의 철학은 이 한 줄에 담겨 있습니다. 첫 시도가 완벽할 필요는 없습니다. 반복할수록 결과물이 다듬어집니다.

### 3단계 워크플로우

```mermaid
flowchart LR
    A["1️⃣ Specs"] --> B["2️⃣ Planning"] --> C["3️⃣ Building"]
    C <--> D(("🔄 Ralph Loop"))
```

### 주요 원칙

1. **루프 안에서 일하지 말고 루프를 밖에서 관리합니다**: 코드는 에이전트가 만지게 두고, 사람은 에이전트가 일할 환경을 손봅니다
2. **backpressure가 지시를 대신합니다**: 테스트·타입체크·린트가 잘못된 결과를 자동으로 반려합니다
3. **계획은 일회용입니다**: 어긋난 계획을 고쳐 쓰는 것보다 새로 뽑는 편이 쌉니다
4. **실패도 데이터입니다**: 반복할 때마다 실패를 딛고 접근을 고칩니다



### 4.2 Ralph TUI (Terminal UI Orchestrator)

**실시간 시각화와 세션 관리를 제공하는 터미널 UI입니다.**

- GitHub: [subsy/ralph-tui](https://github.com/subsy/ralph-tui)
- 문서: [ralph-tui.com](https://ralph-tui.com)

Ralph Loop를 돌려 두면 에이전트가 지금 무엇을 하고 있는지 보이지 않습니다.
Ralph TUI는 이 문제를 해결하는 터미널 기반 오케스트레이터로, AI 코딩 에이전트(Claude Code, OpenCode, Factory Droid)를 작업 트래커(prd.json, Beads)에 연결하여 자율적으로 실행합니다.

```bash title="bash"
# 설치 (Bun 필요)
bun install -g ralph-tui

# 프로젝트 설정
cd your-project
ralph-tui setup

# AI로 PRD 생성
ralph-tui create-prd --chat

# Ralph 실행!
ralph-tui run --prd ./prd.json
```

**주요 특징:**

- **실시간 TUI 대시보드**: 에이전트 출력, 작업 진행 상황 실시간 확인
- **세션 영속성**: 일시 중지/재개, 크래시 복구 지원
- **다중 에이전트 지원**: Claude Code, OpenCode, Factory Droid
- **다중 트래커 지원**: prd.json (단순), Beads (Git 기반, 의존성 관리)
- **서브에이전트 추적**: 중첩된 에이전트 호출 시각화
- **샌드박스 실행**: `--sandbox` 옵션으로 격리된 환경에서 실행

**실행 흐름:**

```mermaid
flowchart TD
    A[1. Select Task] --> B[2. Build Prompt]
    B --> C[3. Execute Agent]
    C --> D[4. Detect Complete]
    D --> E{5. Done?}
    E -->|No| A
    E -->|Yes| F[Complete]
```

### 4.3 Vercel ralph-loop-agent (TypeScript SDK)

**AI SDK와 통합된 TypeScript 구현체입니다.**

- GitHub: [vercel-labs/ralph-loop-agent](https://github.com/vercel-labs/ralph-loop-agent)

JavaScript/TypeScript 프로젝트에서 프로그래밍 방식으로 Ralph Loop를 구현하고 싶다면 이 라이브러리가 최적입니다.
Vercel의 AI SDK를 감싸서 검증 콜백과 컨텍스트 요약 기능을 제공합니다.

```bash title="bash"
npm install ralph-loop-agent
```

**특징:**

- **AI SDK 완전 호환**: AI Gateway 문자열 형식 지원

- **컨텍스트 관리**: 장기 실행 루프를 위한 내장 요약 기능
- **검증 콜백**: `verifyCompletion` 함수로 완료 조건 커스터마이징

<Callout type="info">
**완료 감지 메커니즘**

### 5.4 TDD 기반 개발

```bash title="bash"
/ralph-loop "Implement user authentication using TDD.
Process:
1. Write failing test for next requirement
2. Implement minimal code to pass
3. Run tests
4. If failing, fix and retry
5. Refactor if needed
6. Repeat for all requirements

Requirements:
- JWT token generation
- Password hashing with bcrypt
- Login/logout endpoints
- Token refresh mechanism

Output <promise>DONE</promise> when all tests green." \
--max-iterations 50 \
--completion-promise "DONE"
```

### 5.5 마이그레이션 작업

```bash title="bash"
/ralph-loop "Migrate all tests from Jest to Vitest.
Steps:
1. Identify Jest test files
2. Convert imports to Vitest equivalents
3. Update mock syntax
4. Run tests
5. Fix any failing tests
6. Update package.json scripts

Output <promise>MIGRATION_COMPLETE</promise> when:
- All tests converted
- No Jest dependencies remain
- All tests passing" \
--max-iterations 50 \
--completion-promise "MIGRATION_COMPLETE"
```

## 7. 실전 예시: ralph-loop-agent (TypeScript)

TypeScript/JavaScript 프로젝트에서 프로그래밍 방식으로 Ralph Loop를 구현하는 방법입니다.

### 7.1 설치

```bash title="bash"
npm install ralph-loop-agent
# 또는
yarn add ralph-loop-agent
# 또는
pnpm add ralph-loop-agent
```

### 7.2 기본 사용 예시

```typescript title="ts"
import { iterationCountIs, RalphLoopAgent } from "ralph-loop-agent"

const agent = new RalphLoopAgent({
  model: "anthropic/claude-opus-4.5",
  instructions: "You are a helpful coding assistant.",
  stopWhen: iterationCountIs(10),
  verifyCompletion: async ({ result }) => ({
    complete: result.text.includes("DONE"),
    reason: "Task completed successfully",
  }),
})

const { text, iterations, completionReason } = await agent.loop({
  prompt: "Create a function that calculates fibonacci numbers",
})

console.log(text)
console.log(`Completed in ${iterations} iterations`)
console.log(`Reason: ${completionReason}`)
```

### 7.3 도구(Tool)와 함께 사용

```typescript title="ts"
import { tool } from "ai"
import { iterationCountIs, RalphLoopAgent } from "ralph-loop-agent"
import { z } from "zod"

const agent = new RalphLoopAgent({
  model: "anthropic/claude-opus-4.5",
  instructions: "You help users with file operations.",
  tools: {
    readFile: tool({
      description: "Read a file from disk",
      parameters: z.object({ path: z.string() }),
      execute: async ({ path }) => {
        const fs = require("fs").promises
        const content = await fs.readFile(path, "utf-8")
        return { content }
      },
    }),
    writeFile: tool({
      description: "Write content to a file",
      parameters: z.object({
        path: z.string(),
        content: z.string(),
      }),
      execute: async ({ path, content }) => {
        const fs = require("fs").promises
        await fs.writeFile(path, content)
        return { success: true }
      },
    }),
  },
  stopWhen: iterationCountIs(10),
  verifyCompletion: ({ result }) => ({
    complete: result.text.includes("All files updated"),
  }),
})

const stream = await agent.stream({
  prompt: "Build a calculator module with add, subtract, multiply, divide functions",
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

### 7.4 마이그레이션 에이전트 예시

```typescript title="ts"
import { iterationCountIs, RalphLoopAgent } from "ralph-loop-agent"

const migrationAgent = new RalphLoopAgent({
  model: "anthropic/claude-opus-4.5",
  instructions: `You are migrating a codebase from Jest to Vitest.

For each iteration:
1. Find one Jest test file that hasn't been migrated
2. Convert it to Vitest syntax
3. Run the tests to verify
4. Move to the next file

When all files are migrated and tests pass, include "MIGRATION_COMPLETE" in your response.`,
  stopWhen: iterationCountIs(50),
  verifyCompletion: ({ result }) => ({
    complete: result.text.includes("MIGRATION_COMPLETE"),
    reason: "All Jest tests migrated to Vitest",
  }),
})

async function runMigration() {
  console.log("Starting Jest to Vitest migration...\n")

  const { text, iterations, completionReason } = await migrationAgent.loop({
    prompt: "Begin the Jest to Vitest migration. Start by analyzing the current test structure.",
  })

  console.log("\n--- Migration Complete ---")
  console.log(`Iterations: ${iterations}`)
  console.log(`Reason: ${completionReason}`)
}

runMigration()
```

### 7.5 스트리밍 출력

```typescript title="ts"
const stream = await agent.stream({
  prompt: "Build a todo API",
})

// 실시간 출력
for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}

// 최종 결과
const result = await stream.finalResult
console.log(`\nCompleted in ${result.iterations} iterations`)
```

**참고**: 스트리밍 모드는 검증을 통과하거나 마지막 반복에 이를 때까지 스트리밍 없이 돌고, 마지막 반복만 스트리밍으로 내보냅니다.

## 8. PRD 기반 작업 관리

Ralph의 핵심은 잘 정의된 PRD(Product Requirements Document)입니다.

### 8.1 효과적인 PRD 작성

```markdown title="markdown"
# Feature: User Authentication

## Overview

Implement secure user authentication with JWT tokens.

## User Stories

### US-001: User Registration

**As a** new user
**I want to** create an account
**So that** I can access the application

**Acceptance Criteria:**

- [ ] Email validation
- [ ] Password strength requirements (8+ chars, 1 uppercase, 1 number)
- [ ] Duplicate email check
- [ ] Welcome email sent on success

**Technical Notes:**

- Use bcrypt for password hashing
- Store in PostgreSQL users table

### US-002: User Login

**As a** registered user
**I want to** log in with my credentials
**So that** I can access my account

**Acceptance Criteria:**

- [ ] Email/password validation
- [ ] JWT token generation
- [ ] Refresh token mechanism
- [ ] Rate limiting (5 attempts per minute)

### US-003: Password Reset

**As a** user who forgot my password
**I want to** reset my password
**So that** I can regain access

**Acceptance Criteria:**

- [ ] Reset email with secure token
- [ ] Token expires in 1 hour
- [ ] Password update functionality
```

### 8.3 PRD 크기 가이드라인

**중요:** PRD 항목 하나는 컨텍스트 한 번으로 끝낼 수 있을 만큼 작아야 합니다.

- 좋은 예: "POST /users 엔드포인트 구현"
- 나쁜 예: "전체 인증 시스템 구현"

큰 작업은 더 작은 단위로 나눕니다.

## 9. Best Practices와 주의사항

### 9.1 안전 메커니즘

```bash title="bash"
# 항상 max-iterations 설정
/ralph-loop "..." --max-iterations 20

# Ralph TUI에서도
ralph-tui run --iterations 10

# 비용 모니터링
# Claude Code: ~/.config/claude/usage.json 확인
# API 사용량: Anthropic Console에서 확인
```

### 9.2 효과적인 프롬프트 작성

```markdown title="markdown"
# 좋은 프롬프트

Build a REST API for todos.

Success Criteria:

- All CRUD endpoints working
- Input validation with Zod
- Tests passing (>80% coverage)
- No TypeScript errors

When complete, output: <promise>DONE</promise>
When stuck after 15 iterations:

- Document blockers
- List attempted solutions
- Suggest alternatives

# 나쁜 프롬프트

Build a todo app and make it good.
```

### 9.3 역압력(Backpressure) 설정

프로젝트에 자동 검증부터 걸어 둡니다:

```json title="json"
// package.json
{
  "scripts": {
    "test": "vitest",
    "lint": "eslint . --ext .ts,.tsx",
    "typecheck": "tsc --noEmit",
    "validate": "npm run typecheck && npm run lint && npm run test"
  }
}
```

`AGENTS.md`에 명시:

```markdown title="markdown"
## Validation (run before every commit)

npm run validate

⚠️ DO NOT commit if validation fails.
```

### 9.4 보안 고려사항

Ralph는 `--dangerously-skip-permissions`가 필요한 경우가 많으니, 샌드박스 환경에서 실행해야 합니다:

```bash title="bash"
# Ralph TUI 샌드박스 모드
ralph-tui run --sandbox

# Docker로 격리
docker run -it --rm \
  -v $(pwd):/workspace \
  -w /workspace \
  node:20 \
  bash -c "./ralph.sh"
```

### 9.5 비용 관리

| 작업 규모           | 예상 반복 | 예상 비용 |
| ------------------- | --------- | --------- |
| 간단한 기능         | 5-10      | $1-5      |
| 중간 기능           | 20-30     | $10-30    |
| 대규모 마이그레이션 | 50-100    | $50-150   |

**팁:**

- 먼저 반복 수를 작게 잡고 테스트합니다
- 사람이 지켜보면서 프롬프트를 다듬습니다
- 자신감이 붙은 뒤에 AFK(Away From Keyboard)로 돌립니다

## 10. 마무리

Ralph Loop에서 사람이 하는 일은 코드가 아니라 환경을 만지는 것입니다. 시작은 네 가지면 됩니다:

1. **명확한 목표 정의** (PRD)
2. **자동 검증 설정** (테스트, 린트)
3. **적절한 도구 선택**
   - CLI 환경: Claude Code Plugin
   - 시각적 모니터링: Ralph TUI
   - 프로그래밍 통합: ralph-loop-agent
4. **루프 실행** (그리고 커피 마시기)
